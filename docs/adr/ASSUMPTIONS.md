# Assumptions

Where the v0.1 spec is silent or outdated. A1–A24 were recorded in phase 1. A25 was added in M0. A26–A28 were added in M1. A29–A32 were added in M2. A33–A34 were added in M3. A35–A36 were added in M4. A37 was added in M5. A38 was added in M6. A39–A42 were added in M7. A43–A47 were added in M8. A48–A50 were added in M9. A51–A53 were added in M10. A54–A61 were added in M11. A62–A64 were added in M12.

| Id | Decision | Reason |
| --- | --- | --- |
| A1 | Maven instead of Gradle; Spring Boot 4.1.2 instead of "Spring Boot 3"; seeded JUnit tests instead of jqwik; SeaweedFS + `pgsty/silo` instead of `minio/minio`; AWS CRT async HTTP client. | User's choice (Maven). Boot 3.x OSS support ended 30 Jun 2026. jqwik 1.10 targets JUnit Platform 1.x, the project is on JUnit 6. `minio/minio` left Docker Hub. The SDK's Netty client is on Netty 4.1 and would clash with Netty 4.2. |
| A2 | `topics.deleted_at TIMESTAMPTZ NULL`; `UNIQUE(name)` replaced by a partial unique index `WHERE deleted_at IS NULL`. | §10.1 says delete "marks the topic"; §8 has no column for it, and a name must be reusable. |
| A3 | `LAKEWIRE_BROKER_ID` must be a positive integer, stored as TEXT in `brokers.id`; it's the Kafka node id. | Kafka node ids are int32; §8 uses TEXT. |
| A4 | Initial ranges: ApiVersions 0–3 (kept), Metadata 1–9, Produce 3–12, Fetch 4–12, ListOffsets 1–6, InitProducerId 0–4, CreateTopics 2–6, DeleteTopics 1–5. Mins = kafka-clients 4.4.0 baselines where Kafka 4.0 removed older ones. Max stays below topic-ID versions (Metadata ≥ 10, Produce/Fetch ≥ 13, CreateTopics 7, DeleteTopics 6) and KIP-939's unstable InitProducerId v6. Changed only with compat tests. | §10.1 "pinned by compatibility tests rather than guessed"; v0.1 has no topic UUIDs. |
| A5 | Metadata `leaderEpoch = -1` (unknown); the broker ignores `currentLeaderEpoch` in Fetch. | Leadership is only a routing hint (§10.1); a constant epoch could make clients ignore leader changes. |
| A6 | LKW1 `broker_id` = u16 length + UTF-8 bytes. | §7.2 gives no width. |
| A7 | On fencing (heartbeat false or commit epoch reject) the broker fails buffered requests with `NOT_LEADER_OR_FOLLOWER`, then re-registers with a new epoch (no process exit). | Simplest recovery that keeps clients retrying. |
| A8 | Cluster id = a random Kafka-style base64 UUID stored once in a one-row `cluster` table (Flyway V1). | Metadata needs a stable cluster id; §8 is silent. |
| A9 | New small module `lakewire-cost` (shared by CLI and admin). Tiered-storage model = classic transfer costs + hot set on broker disk for 1 day, rest on S3 (configurable). | §10.2 and §10.4 both need the model; §15.1 has no home for it. |
| A10 | Metadata never auto-creates topics. | Explicit CreateTopics is in scope; auto-create isn't mentioned. |
| A11 | Topic configs accepted: `retention.ms` (default 7 days, like Kafka) and `cleanup.policy=delete`. Anything else, including `retention.bytes` and `compact`, → `INVALID_CONFIG`. | P0 has only time-based retention; key compaction is P2. Rejecting beats silently ignoring. |
| A12 | Defaults: `buffer.max.bytes` 64 MiB, `upload.max.concurrency` 4, block cache 256 MiB, segment-index cache 100k entries. | PRD gives linger 200 ms and 8 MiB objects only. |
| A13 | Storage retries exhausted → `KAFKA_STORAGE_ERROR` (retriable). | Not listed in §10.1's mapping; it's Kafka's code for this case. |
| A14 | ListOffsets by timestamp is batch-granular (first batch with `maxTimestamp >= t`). | Avoids decompressing batches; the result is ≤ Kafka's exact offset, so consumers only see a few extra records. |
| A15 | InitProducerId with a transactional id → `INVALID_REQUEST`. Unknown producer id in InitProducerId → allocate a new id. | Transactions are a non-goal (§2.3); the PRD names no code. |
| A16 | Client zone = `az=<zone>` at the end of `client.id`, after `,` or `;`. | Figure 1 shows `client.id=…,az=a`. |
| A17 | Orphan TTL 10 min, GC/retention period 1 min, DELETE_PENDING sweep 30 s, ref audit 5 min, producer-state expiry check 1 h; grace 5 min and producer TTL 7 days from the PRD. | TTL must exceed upload + commit time and the lease. |
| A18 | Broker metrics on `:9094/metrics` (JDK HttpServer). 9093 stays reserved for v0.2 gRPC. | §10.2 only gives the admin's actuator endpoint. |
| A19 | Docs pages live as Markdown in `docs/` and are published through the existing `web/` Next.js site as a static export to GitHub Pages. | §13 D16 says GitHub Pages; the repo already has `web/`. |
| A20 | One commit entry = one Produce partition payload, which is exactly one RecordBatch (kafka-clients enforces one batch per partition for Produce v3+), so idempotence works per chunk. | Fits §7.2 chunks and §9.2 arrays without splitting chunks. |
| A21 | A multi-stage `Dockerfile` (not Jib) builds the images, so `git clone` + `docker compose up` is 2 commands. The admin ships as a second image `lakewire-admin`. | §13 D15 check; keeps Spring out of the CLI jar. |
| A22 | Brokers, `lakewire dev` and `lakewire worker` run Flyway `migrate` at start (Flyway's PG lock serialises them); admin only validates. | Simplest way to get a fresh clone to a migrated schema. |
| A23 | `lakewire-testkit` in v0.1 is the shared internal test infrastructure; publishing it to Maven Central is v1.0 (§18). | §15.1 lists it; §18 puts the public module at v1.0. |
| A24 | Zone-aware Metadata (leader in the client's zone) ships in v0.1; the gRPC shared cache does not. | §10.1 and D9 put zone-aware Metadata in v0.1; §6 puts the shared cache in v0.2. |
| A25 | Silo is constructed with Testcontainers `MinIOContainer` after `DockerImageName.asCompatibleSubstituteFor("minio/minio")`. | `MinIOContainer` in Testcontainers 2.0.5 allowlists only `minio/minio`. `pgsty/silo` is the image A1 requires. |
| A26 | `sl_register_broker` and `sl_heartbeat` take optional `p_lease_ms bigint DEFAULT 10000`. Java passes `CoordinatorConfig.leaseMs`. Expiry is still `now() + p_lease_ms`. Commit result `idx` is the 0-based input position (`generate_subscripts - 1`). | The prompt's SQL signature has no lease argument, and it also says the lease length comes from config. A default keeps both. Java lists are 0-based. |
| A27 | Coordinator env: `LAKEWIRE_PG_URL`, `LAKEWIRE_PG_USER`, `LAKEWIRE_PG_PASSWORD`, `LAKEWIRE_MIGRATE` (default true), `LAKEWIRE_LEASE_MS` (default 10000), `LAKEWIRE_HEARTBEAT_MS` (default 2000), `LAKEWIRE_GROUP_COMMIT` (default false; ADR-001). | The PRD names the lease and the flag, not the variable names. Heartbeat interval is the caller's schedule; M1 does not start that thread. |
| A28 | A commit that accepts nothing inserts `DELETE_PENDING` with `delete_after = now() + interval '5 minutes'`. `sl_commit_object_rowloop` is lab-only and is not the production path. | §9.1 grace default is 5 minutes (A17). There is no settings table in v0.1. The Day-3 lab needs the per-row loop beside the set-based function. |
| A29 | LKW1 index `byte_start` is the absolute offset from the first byte of the object. A store that does not answer the second probe PUT with 412 falls back to HEAD-before-PUT; the probe result is logged. | Range GET needs a file offset. §7.2 does not say whether `byte_start` is relative to the body or the object. `If-None-Match` is not universal on S3-compatible stores. |
| A30 | S3 user metadata `crc32c` is the unsigned decimal CRC32C of the object bytes. 5xx and connection failures retry 3 times, waiting `20ms * attempt` plus up to 20ms of jitter. A 412 on a retry is success only when HEAD size and `crc32c` match. | The prompt requires that metadata comparison and bounded jittered retries, and names neither the key nor the limits. |
| A31 | `LAKEWIRE_S3_BUCKET` is required. `LAKEWIRE_S3_REGION` defaults to `us-east-1`. `LAKEWIRE_S3_ENDPOINT` is optional. `LAKEWIRE_S3_PATH_STYLE` defaults to true. `LAKEWIRE_S3_CONDITIONAL_PUT` defaults to true. `LAKEWIRE_S3_ACCESS_KEY` and `LAKEWIRE_S3_SECRET_KEY` are used together when both are set; otherwise the default provider chain is used. | The prompt names `LAKEWIRE_S3_*` and the default chain, not each variable. SeaweedFS and Silo need path-style access. |
| A32 | `LocalFsObjectStore.put` refuses an existing key before `ATOMIC_MOVE`, under the store lock. | On Windows, `Files.move(..., ATOMIC_MOVE)` replaces an existing file instead of throwing `FileAlreadyExistsException`. |
| A33 | `LAKEWIRE_STORAGE` is `fs` (default) or `s3`. `LAKEWIRE_DATA_DIR` defaults to `data`. `LAKEWIRE_BROKER_ID` defaults to 1. `LAKEWIRE_ZONE` defaults to `local`. `LAKEWIRE_ADVERTISED_HOST` defaults to `localhost`. An advertised port of 0 means the bound port. | The prompt names the variables and not every default. Port 0 is how tests bind an ephemeral port. |
| A34 | CreateTopics replica assignments are ignored. A broker endpoint is `host:port`, split on the last colon. | The prompt accepts a replication factor and does not mention manual assignments. §8 stores one endpoint string. |
| A35 | Produce tuning env: `LAKEWIRE_LINGER_MS` (200), `LAKEWIRE_OBJECT_MAX_BYTES` (8 MiB), `LAKEWIRE_BUFFER_MAX_BYTES` (64 MiB), `LAKEWIRE_UPLOAD_CONCURRENCY` (4), `LAKEWIRE_OBJECT_PREFIX` (empty). A full buffer or a single chunk larger than the buffer fails the partition with `REQUEST_TIMED_OUT`. An ambiguous commit is retried up to 3 times; each call borrows a new pool connection, and `sl_commit_object` returns the stored offsets when the key already committed. | A12 names the numeric defaults. The prompt names neither the variables nor the retry count. |
| A36 | Produce with a non-null `transactionalId`, and a transactional or control batch, is rejected. The id is `INVALID_REQUEST`. The batch is `INVALID_RECORD`. | Transactions are a non-goal (§2.3). A15 covers InitProducerId only. |
| A37 | ListOffsets accepts `-2` (log start), `-1` (high watermark) and timestamps `>= 0`. Any other timestamp is `INVALID_REQUEST`. Fetch isolation level is ignored; both levels read the high watermark, and `lastStableOffset` is that watermark. | There are no transactions in v0.1. The prompt names the three lookup forms and not the other negative sentinels. |
| A38 | A produce epoch other than `producer_ids.producer_epoch` is `INVALID_PRODUCER_EPOCH`. InitProducerId when Postgres is unreachable is `COORDINATOR_NOT_AVAILABLE`. | The prompt names the less-than epoch case. A higher epoch was not issued by InitProducerId. Produce stays on `REQUEST_TIMED_OUT` when the coordinator is down. InitProducerId uses the retriable coordinator code the prompt names. |
| A39 | `sl_heartbeat` extends the lease only when the epoch matches and `lease_expires_at > now()`. An expired lease returns false; the broker re-registers. | A paused broker must not refresh its lease on unpause and then commit the upload it started under the old epoch. |
| A40 | The broker image runs the shaded CLI (`lakewire broker`). Flyway and AWS service files are merged with `ServicesResourceTransformer`. | M11. |
| A41 | `LakeWireCluster` builds that Dockerfile with `docker build`. Testcontainers `ImageFromDockerfile` is not used. | Its context upload is a 1 KiB pipe. On Windows the pipe fills and the client blocks after the daemon has already produced the image. |
| A42 | A failed S3 conditional-PUT probe logs a warning and falls back to HEAD-before-PUT instead of aborting broker start. Cluster tests talk to SeaweedFS directly; only the pause test routes PUTs through Toxiproxy. | SeaweedFS and Toxiproxy can close the first probe sockets before the S3 API is ready. Startup should not depend on that race. |
| A43 | The worker advisory lock is `pg_try_advisory_lock(87001108)`. | The prompt asks for a constant; session lock release on disconnect is the leadership signal. |
| A44 | Audit violations increment in-process `WorkerMetrics` (`lakewire_audit_violations_total` by invariant). Prometheus export is M10. | M8 requires the metric name; M10 serves `/metrics`. |
| A45 | I8 ages leaked keys from `ObjectHead.lastModified` against the checker clock, using orphan TTL + GC period. | Bucket listings have no Postgres row to compare to `now()`. |
| A46 | Worker env: `LAKEWIRE_WORKERS` (default true), `LAKEWIRE_ORPHAN_TTL_MS`, `LAKEWIRE_GC_PERIOD_MS`, `LAKEWIRE_RETENTION_PERIOD_MS`, `LAKEWIRE_DELETE_SWEEP_MS`, `LAKEWIRE_REF_AUDIT_MS`, `LAKEWIRE_AUDIT_HEAD_CAP` (100), `LAKEWIRE_PRODUCER_TTL_MS`, `LAKEWIRE_PRODUCER_EXPIRY_PERIOD_MS`, `LAKEWIRE_GRACE_MS`, `LAKEWIRE_WORKER_LOCK_RETRY_MS`. Defaults from A17. | The PRD names periods, not the variables. |
| A47 | Topic `retention.ms` of -1 skips time-based prefix deletion. | CreateTopics already accepts -1, which is Kafka infinite retention. |
| A48 | The 50×10m soak is `LakeWireVerify --soak N --duration 10m`. Nightly CI runs one 30m job. M9 records the 3-minute smoke. Overnight ≥100 runs stay a launch gate (§12), not this milestone's local loop. | A 50×10m loop is ~8 hours; the prompt also requires a 3-minute PR smoke. |
| A49 | Retention-storm writes `retention.ms` through `sl_set_topic_retention`. AlterConfigs is not a v0.1 API. | SupportedApi has no IncrementalAlterConfigs. |
| A50 | Cluster SlowS3 is Toxiproxy latency on the broker↔S3 proxy. `FaultInjectingObjectStore` remains the in-process 5xx/slow/404 wrapper. | Brokers in `LakeWireCluster` do not share the test JVM's ObjectStore. |
| A51 | Classic storage in `lakewire-cost` is 3 × EBS gp3 list ($0.08/GB-month). No extra headroom multiplier. | §12.1 shows storage separately and mentions headroom only as a qualitative note. |
| A52 | `LAKEWIRE_METRICS_PORT` 0 binds an ephemeral port (tests). Production default remains 9094 (A18). | Parallel ITs would collide on a fixed 9094. |
| A53 | First `bench/e2e` CSVs are laptop-labelled 1-broker SeaweedFS runs, not a compose 3-broker cluster. Compose scripts wait for M11. | M10 compose still has only Postgres + SeaweedFS. |
| A54 | `lakewire dev` stores Postgres and objects under `~/.lakewire/dev` (`--home` overrides). Zonky `synchronous_commit` is set to `on`. | The prompt names the directory and not the Zonky default, which is off. |
| A55 | Admin reads `LAKEWIRE_*` from the Spring `Environment` (env vars and test properties). It never migrates; `Coordinator.validate()` runs at bean creation. | A22. Tests cannot rewrite `System.getenv`. |
| A56 | Compose brokers advertise `localhost` plus 9092/9192/9292 so host clients work. Seaweed compose identity is `lakewire/lakewire` to match `.env.example`. | Leadership is a routing hint; brokers do not connect to each other in v0.1. |
| A57 | `DevModeIT` allows 30 s for first binary unpack. First measured ready time on this laptop was 14.7 s. | Zonky extracts Postgres 18.7 on the first run. |
| A58 | Admin port is `LAKEWIRE_ADMIN_PORT` (default 8080). | §10.2 names 8080, not the variable. |
| A59 | Admin pins `logback-core` and `logback-classic` 1.6.7 over Boot 4.1.2's `logback-core` 1.5.38. HikariCP stays 7.1.0. | Mixed logback artifacts warn at startup. |
| A60 | The Boot repackage jar uses classifier `exec` so failsafe still sees a plain jar. | Fat jars hide `@SpringBootConfiguration` from tests. |
| A61 | The CLI shade jar is attached as classifier `bin`; the main artifact stays thin. | Failsafe otherwise loads Zonky binaries twice (fat jar + Maven dep). |
| A62 | GitHub Pages deploys a static `site/` copy of `docs/` plus `web/public` HTML. Next.js App Router files under `web/src/app` are not rebuilt. | Those route files are empty stubs; A19 forbids rewriting the marketing pages. `tallyfold.html` stays the landing page. |
| A63 | Pages workflow uses `upload-pages-artifact` v3.0.1 and `deploy-pages` v4.0.5 (not in the pin table). | Required to publish the static catalog. |
| A64 | JReleaser ships the CLI `*-bin.jar` as a `SINGLE_JAR` distribution; signing is off. Dry run still needs `JRELEASER_GITHUB_TOKEN` (any placeholder). Plugin is not inherited by modules. | No signing key in CI. Version stays `0.1.0-SNAPSHOT` until a separate bump. |
